# 平面直角座標系の端末内判定データ

出典：国土交通省「国土数値情報（行政区域データ、2023年）」をEz Viewerで編集・加工して作成。
国の機関がこの加工データや判定処理を作成・保証したものではありません。

- 元データ：[国土数値情報 行政区域 N03](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-v3_1.html)（2023年1月1日、JGD2011緯度経度）
- 使用アーカイブ：[N03-20230101_GML.zip](https://nlftp.mlit.go.jp/ksj/gml/data/N03/N03-2023/N03-20230101_GML.zip)
- SHA-256：`d0cf37cf450438a62b14007179cbc7bd47b085f20465f6a32f7eaad8ac962e7a`
- 系の割当根拠：[国土地理院 平面直角座標系](https://www.gsi.go.jp/LAW/heimencho)
- 元データの利用条件：[国土数値情報利用約款](https://nlftp.mlit.go.jp/ksj/other/agreement.html)。同約款が定める出典・加工表示等を維持してください。

## 加工内容

都道府県・市町村属性を国土地理院の適用区域に対応させ、I～XIX系ごとに行政区域を統合しました。
北海道の市町村・総合振興局等による区分、鹿児島県の島しょ部、東京都の南方諸島、沖縄県の東西区分を含みます。

スマホの負荷を抑えるため、別の系の区域付近は約1m相当（緯度経度0.00001度）の簡略化許容差、そこから離れた海岸線等は約100m相当（0.001度）を使用しています。数値は100万倍の整数へ量子化し、差分を可逆圧縮した文字列で保持します。**これは元の行政界やGPSに1m・0.1mの精度があるという意味ではありません。**

小島・微小な区域は一部を代表点にし、同じ系の約100m格子内でまとめています。陸地ポリゴンの内側を優先し、内側に見つからない場合だけ、3km以内の海岸・小島に近い系を補助候補とします。国土の適用範囲外は既存の原点距離による近似候補を使用します。

## 実行と制限

- データはアプリと一緒に読み込みます。座標系を調べるための逆ジオコーダや位置情報の外部送信はありません。従来の背景タイル等の通信は別です。
- 最初の判定時に小さな空間索引を作り、必要な区域・小島の座標だけを展開してキャッシュします。パン・ズーム・回転の描画ループには追加しません。
- 図面に明示・保存・手動設定された座標系を、このデータを理由に書き換えません。自動候補の取得元だけを変更しています。
- 旧版が自動で保存した系と利用者が手動設定した系は、既存の保存形式では区別できません。過去に誤った系が保存済みの図面は、勝手に上書きせず利用者が設定で修正する必要があります。
- 行政界の近く、境界未確定区域、海上、埋立地、元データ以後に変化した区域等では候補が適切でない場合があります。図面の正式な座標系を確認し、必要時は設定から手動選択してください。
- 行政界の表示用・境界確定用・測量成果用のデータではありません。元のN03にも未確定境界等が含まれます。

## 再生成（開発時のみ）

Pythonの `pyshp==3.1.6`、`shapely==2.1.2`、`numpy==2.5.2` を使用します。これらはアプリの実行時依存ではありません。
公開元ZIPを任意の作業用フォルダーへ取得し、リポジトリ直下で以下を実行します。

```text
python scripts/build-japan-plane-zone-data.py <N03-20230101_GML.zip> --cache-dir <作業用キャッシュ> --output data/japan-plane-zones.js
node validate-japan-plane-zones.js
```

ZIP・中間キャッシュはリポジトリへ追加しません。生成用スクリプトは元ZIPのSHA-256を照合します。
データまたは形式を更新した場合は、`index.html` のデータ・判定モジュールのキャッシュ識別子も更新してください。
