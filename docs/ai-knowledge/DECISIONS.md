# 設計判断と確定仕様

## D-001 Gitをコード状態の正本にする

- 状態: `検証済み`
- 判断: 外部知能にはコード全文を複製せず、コミット、対象範囲、根拠、テスト、戻し先を記録する。
- 理由: 文書の陳腐化と常時コンテキストの肥大化を防ぐ。
- 確認回数: 2以上（複数の正常コミットと回帰テスト運用で確認）。

## D-002 会話をそのまま確定仕様にしない

- 状態: `検証済み`
- 判断: ユーザー報告は重要な観察だが、コード、再現、仕様書、正常ファイル、テストのいずれかで裏付けてから確定仕様へ移す。
- 例外: UI文言など、ユーザーが明示的に最終決定し、実装と検証が一致したもの。
- 確認回数: 2以上。

## D-003 既存の正常機能を横断的に書き換えない

- 状態: `検証済み`
- 判断: 修正は最小の機能境界に限定し、隣接機能の回帰テストを必ず行う。正常コミット全体を戻すのではなく、必要差分だけを扱う。
- 理由: 単一HTML内で機能が近接しており、SFC、ラスター、写真、地形、ポップアップの相互回帰が過去に起きやすい。
- 確認回数: 2以上。

## D-004 表示状態と編集データを分離する

- 状態: `検証済み`
- 判断:
  - パン、拡大縮小、回転、GPS再中心化など表示だけの変更では完全復元JSONを保存しない。
  - 手書き、写真、レイヤー削除、レイヤー色など成果へ影響する変更は保存する。
- 根拠: `48129bf`、`dde4fac`、性能・復元テスト。
- 確認回数: 2。

## D-005 DEM1Aを最優先し、欠損点だけDEM5Aで補完する

- 状態: `検証済み`
- 判断:
  - DEM1Aが存在する点を、画面全体の取得率を理由にDEM5Aへ置き換えない。
  - 欠損点だけDEM5Aで補う。
  - 広域表示の軽量化は格子間隔で調整し、標高源の優先順を変えない。
  - 等高線CAD化は表示倍率と無関係に高精度側を優先する。
- 根拠: 現行コードのDEM優先処理、`bb08104`、地形・等高線検証。
- 確認回数: 2以上。

## D-006 写真のドラッグ＆ドロップとファイル選択を区別する

- 状態: `検証済み`
- 判断:
  - PCのドラッグ＆ドロップは旧写真一式の置換。
  - 写真選択ボタンは追加・統合。
  - 置換は新しい有効写真が1枚以上得られてから確定する。
- 根拠: `ffb3427` と写真帳検証。
- 確認回数: 1。別の回帰確認後に常設扱いを再評価する。

## D-007 ブラウザFile参照は実行時データとして扱う

- 状態: `検証済み`
- 判断: 写真の `File` は同じ起動中だけ非列挙プロパティとMapで保持し、復元JSONへ埋め込まない。
- 理由: ブラウザのファイル参照はJSONへ永続化できず、大容量写真を復元データへ入れると保存と操作が重くなる。
- 根拠: `f42ca33` と写真帳実行時テスト。
- 確認回数: 1。

## D-008 法務局データの容量確認はスマホだけ行う

- 状態: `検証済み`
- 判断:
  - スマホは全取得前に容量を表示し、了承後にダウンロードする。
  - 容量がメタデータに無い時はHEAD、次に1バイトRangeで全体容量を確認する。
  - PCは容量確認を省略し、共通進捗バーは表示する。
- 根拠: `4abdab7` と法務局進捗検証。
- 確認回数: 1。

## D-009 公開は明示依頼時だけ行う

- 状態: `検証済み`
- 判断: 実装、コミット、公開を別工程として扱う。「実装して」だけではpushしない。「公開して」の明示がある場合だけ公開する。
- 確認回数: 2以上。

## D-010 SXF/SFC互換処理は推測で直さない

- 状態: `検証済み`
- 判断: SXF/SFCの配置、文字角度、複合図形、ハッチ、ラスターは、仕様書、正常な他CAD出力、実ファイル比較、読込テストの根拠を揃えて修正する。
- 理由: 見た目だけ合わせる修正は他CADでエラーや配置崩れを起こし得る。
- 確認回数: 2以上。

## D-011 スマホ方位追従をGPSから分離する

- 状態: `検証済み`
- 判断:
  - 図面の自動回転は現在地/GPSの開始条件にせず、端末の方位センサーだけで動かす。
  - 初期状態は回転OFF。ファイル選択中には方位許可を要求しない。
  - 方位ボタンはポップアップを出さず、押した時だけ方位許可と自動回転を開始し、再押下で停止する。
  - ホームは自動回転を停止し、図面を読み込み時の角度へ戻す。同じ起動中に勝手に再開しない。
  - センサー値を図面角度へ直接代入せず、最短方向への補間と微小変化の抑制を使う。
  - 通常図面は最大60fps、大規模図面は既存の描画間引きを使い、表示操作として復元保存は行わない。
- 根拠: `e2dfb67`、`90a3a81`、`44f1777`、`25df6cc` と `validate-compass-follow.js`、性能・GPS・実SFC回帰検証。
- 確認回数: 1。別端末での実機確認後に常設扱いを再評価する。

### D-X02 図面読込直後の自動方位追従

- 状態: `廃止`
- 判断: ファイル選択時に方位許可を先取りして初期自動回転させる方式は採用しない。方位回転は方位ボタンから手動開始する。
- 根拠: 実機で英語エラーが表示された観察と、`25df6cc` の手動開始回帰テスト。
- 注意: ファイル入力のchangeやサンプル読込操作へ方位許可要求を再追加しない。
