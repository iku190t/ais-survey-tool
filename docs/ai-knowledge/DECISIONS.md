## D-013 端末既定の図面座標系を図面距離へ自動適用する

- 状態: `廃止`
- 旧判断:
  - スマホで最初にGPSを取得した場所の平面直角座標系を、端末共通の「新しい図面の既定座標系」として1回だけ保存する。
  - 優先順位は、図面別の手動指定、図面別に判定・記憶した座標系、端末既定の順とする。
  - 端末既定は現在地の座標系とは別の状態として保持し、移動のたびに上書きしない。
  - 設定画面から確認・変更・解除でき、解除後は次のスマホGPS取得時に再設定する。

- 確認回数: 2。`fc28eb7` と `7e6f76d` で、未設定図面を安全側へ切り替える必要を別々に確認した。

## D-014 図面との距離には図面別に確認された座標系だけを使う

- 状態: `廃止`
- 判断:
  - 現在地と図面の距離は、図面別に手動指定された平面直角座標系がある場合だけ数値表示する。
  - 図面座標系が未設定なら距離を推測せず、未設定を通知して現在地の最新航空写真へ切り替える。
  - GPS中の最新航空写真は1種類へ固定し、GPS座標の揺れから過去年代検索を繰り返さない。
  - 距離判定はSFC内の全図形を包む外接矩形ではなく、SXF解析で特定した主図面部分を使う。主図面情報が無い旧形式だけ外れ値を除いた図面範囲へ退避する。
  - 現在地座標系への一時切替中は、図面座標で保存された航空写真ラスターを現在地へ再投影しない。GPS終了後に元の表示へ戻す。
- 理由: 誤った6kmは、距離不明より危険である。GPS座標の揺れによる年代再検索は、異なる地点の画像が交互に表示されるように見える点滅を生む。
- 根拠: `fc28eb7`、`7e6f76d`、`bdc4975`、`validate-gps-startup-mode.js`。
- 廃止理由: 実利用ではスマホを現場付近で使う場合がほとんどであり、まれな県外図面のために毎回未設定扱いとするより、現在地の系を初期値として例外だけ手動変更する方が実用的だというユーザー判断を優先した。主図面範囲による距離判定と図面別保存は維持する。

## D-018 Drogger登録を通常GPSと分離し成果は既存編集形式へ載せる

- 状態: `検証済み`
- 判断:
  - Drogger用画面は現在地詳細の題名を動かさず3秒長押しした時だけ開き、通常利用者の画面には常設しない。短押し、途中離し、12pxを超える移動はキャンセルする。
  - 専用処理、標高補正、登録図形、CSVは `drogger-owner-mode.js`、ISG解析と端末保存は `drogger-geoid-model.js` に分離し、SFC読込、図面描画、通常GPSと通常の現在地詳細を置き換えない。
  - 標高は楕円体高から公式ISGモデルのジオイド高とアンテナ高を差し引く。ジオイドをDEMや研究用モデルで代用せず、モデルが無い時も登録を止めず標高だけを「－」にする。
  - 登録成果は既存の編集図形形式を利用して、0.8mm丸と中心十字、点名、標高の3レイヤーとしてSFCメタデータと自動復元へ保存する。
  - Web Geolocation APIに存在しないRTK FIX状態を推測表示せず、鮮度・高度有無でも登録を止めない。表示誤差を見て利用者が登録可否を判断し、高度未取得は「－」として扱う。
  - SFC図面を開いていないGPS専用状態でも登録を許可し、登録点・点名・標高の既存3レイヤー形式を使う。
  - 標高誤差は専用画面とCSVから除外し、最小化中は水平誤差だけを表示する。
  - 登録成功を音で知らせ、末尾が数字の点名は登録ごとに増番する。
- 理由: 専用機器利用を通常利用から隠しつつ、現場登録成果を既存の保存・復元・レイヤー色・Undoから外さないため。
- 根拠: `8628b90`、`749651c`、`b08e05e`、`711ee5a`、`ea0e6f7` とDrogger専用3テスト、杭打ちアプリの実装比較、GPS・復元・実SFC回帰検証。
- 確認回数: 1。Android実機とDrogger接続での観測後に常設判断への昇格を再評価する。

## D-019 図面なしの表示寸法とSFC紙面寸法を分離する

- 状態: `検証済み`
- 判断:
  - 図面縮尺の無い現在地モードでは、Drogger点記号と文字を画面確認用の一定ピクセル寸法で描画する。
  - 登録座標・点名・標高は実座標のまま保持し、表示のために世界座標上の記号径を拡大しない。
  - SFC出力時に対象図面の座標格納方式と縮尺を読み、丸・中心十字を紙面0.8mm、文字を保存済みの紙面mm設定へ再構成する。既定文字高は1.8mmとする。
- 理由: 図面なしでは紙面縮尺を決められない。紙面0.8mmを実座標へ直書きすると0.001m程度の図形になり、画面表示にも計測値にも誤解を生むため。
- 根拠: `92273dd`、`validate-drogger-owner-mode.js`、`validate-drogger-owner-runtime.js`、`validate-real-sfc-rendering.js sample.sfc`。
- 確認回数: 1。実SFC書出を外部CADで確認後に確認回数を更新する。

## D-020 Androidのメール送信はZIPをWeb Shareへ直接渡す

- 状態: `検証済み`
- 判断:
  - Androidだけ、ファイルメニューへ「共有・メール送信」を追加する。
  - 現行SFCを書き出して単一ファイルZIPへまとめ、準備完了後の専用ボタン操作から `navigator.share()` を直接呼ぶ。
  - ZIP MIMEは複数候補を試し、Gmail等の共有先選択はAndroid共有画面へ任せる。
  - PC・iPhoneと通常の保存経路は置き換えない。
- 理由: ZIPを通常ダウンロードするとAndroidでは「アプリで開く」になり、Gmailを含む共有先選択画面へ進まないため。また、ZIP生成の非同期処理後に共有を自動開始するとブラウザのユーザー操作要件を失う場合があるため。
- 根拠: `92273dd`、`validate-android-sfc-share.js`。
- 確認回数: 1。Android実機でGmail共有先が表示されることは追加確認が必要。
