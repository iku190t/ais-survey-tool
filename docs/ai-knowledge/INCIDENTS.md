# 不具合・事故記録

## INC-20260822-01 写真帳で元写真の再選択を求められる

- 状態: `検証済み`
- 観察: PCで写真をドラッグ＆ドロップした直後でも、写真帳Excel出力時に「写真を選んでください」となることがあった。
- 根本原因: 写真項目と元のブラウザ `File` の関連付けがMapだけに依存し、処理途中で参照できない経路があった。
- 修正: `f42ca33` で、写真項目に非列挙の `_sourceFile` を保持し、Mapを予備参照にした。
- 検証: `validate-photo-album-runtime.js` が、直接参照から2枚を復元し、元写真不足0件を確認。
- 再発防止:
  - 同一起動中の写真帳出力で再選択を要求しない。
  - `File` をJSONへ保存しようとしない。
  - 再起動後のファイル再接続と、同一起動中の参照切れを混同しない。
- 正常基準: `BASE-PHOTO-SOURCE-20260822`。

## INC-20260822-02 新しい写真を入れると前回の矢印が復活する

- 状態: `検証済み`
- 観察: 写真レイヤー削除後、新しい写真を読み込むと古い写真方向矢印だけが戻ることがあった。
- 根本原因: 読み込んだSFCに残る旧写真ソース図形と、実行中の写真注記・元写真参照が別に残り、新規読込時に再結合された。
- 修正:
  - 旧写真ソース図形を除去してからライブ写真レイヤーを有効化する。
  - `ffb3427` でPCドラッグ＆ドロップ時に旧写真関連状態を一括置換する。
- 検証: `validate-photo-album-runtime.js` が、レイヤー削除、Undo、再読込前の旧線除去を確認。
- 再発防止: 写真レイヤー削除・新規ドラッグ時は、図形だけでなく写真注記、元写真Map、選択、プレビュー、写真関連履歴を一貫して扱う。
- 正常基準: `BASE-PHOTO-DROP-20260822`。

## INC-20260822-03 パン・拡大縮小・各コマンドが重くなる

- 状態: `検証済み`
- 観察: PC/スマホのパンや拡大縮小の初動が重く、計測・手書き・断面にも遅延を感じる状態があった。
- 根本原因: 表示だけのジェスチャー完了ごとに、1MB超のHTML内データを含む完全復元スナップショットをJSON化・保存していた。大規模図面ではタッチ移動ごとの再描画も過密だった。
- 修正: `48129bf` で表示操作から復元保存を外し、大規模図面のタッチ変形描画を約32ms間隔に制限。終了時に正確な最終描画を行う。
- 検証: `validate-performance-indexes.js`、`validate-recovery-autosave.js`。
- 再発防止: 表示変換のイベントへ `scheduleRecoverySnapshot()` を追加しない。実データ変更は `markMemoChanged()` を通す。
- 正常基準: `BASE-VIEW-PERFORMANCE-20260822`、`BASE-RECOVERY-20260822`。

## INC-20260822-04 法務局データの確認で容量不明になる

- 状態: `検証済み`
- 観察: スマホの法務局データ確認で容量が不明なまま表示されることがあった。
- 根本原因: CKANのresourceメタデータに `size` が無い場合、全ファイル取得前に容量を補う経路がなかった。
- 修正: `4abdab7` でHEADを試し、利用できない場合は1バイトRangeの `Content-Range` 総量を読む。取得本文は即時キャンセルする。
- 検証: `validate-registry-progress-cancel.js` がHEAD→Range代替と13.0MB表示を確認。
- 再発防止: 容量確認のために全ファイルを先行取得しない。PC確認なし、スマホ確認ありの分岐を維持する。
- 正常基準: `BASE-REGISTRY-SIZE-20260822`。

## INC-20260822-05 方位追従の図面回転がカクつく

- 状態: `検証済み`
- 観察: スマホの「現場の向きに追従」で図面回転が段階的に見え、図面によっては処理負荷も上がる。
- 根本原因: 約50msごとに届く方位値を図面角度へ直接反映し、その都度CAD全体を再描画していた。
- 追加で確認した原因: 旧UIでは方位ボタン自体がiPhoneの初回センサー許可開始対象から除外され、Android/WebViewの `absolute=false` なalpha値も捨てていた。さらにiPhoneでは図面解析完了後に許可を要求してもユーザー操作の有効時間を過ぎており、方位ボタンを押すまで初期開始できなかった。応答時定数90msと目標追従率42%の二段階補間も、滑らかだが遅く感じる設定だった。白背景では外側のボタンだけが青く、面積の大きい内側の方位盤が白いまま残るため、追従中でも青状態に見えなかった。
- 修正: `e2dfb67` で滑らかな最短方向補間とGPS分離。`90a3a81` で設定ポップアップを廃止し、方位ボタンを直接ON/OFF、非absoluteの有限alpha値を受付。`44f1777` で応答時定数を45ms、目標追従率を72%へ変更し、`cf87287` で28ms・88%へ高速化した。ファイル選択中の許可先取りは実機で英語エラーが観察されたため、`25df6cc` で完全に廃止し、方位ボタンを押した時だけ許可要求と回転開始を行う方式へ確定した。`3c1b8f4` で追従中の内側方位盤も背景色に関係なく青くした。
- 検証: `validate-compass-follow.js` で黒背景・白背景の実際の計算済み色、初期OFF・事前許可要求0回、iPhone相当で方位ボタン押下時だけ許可要求1回、直接ON/OFF、非absoluteイベント、高速な最短方向補間、ホーム停止と0度復帰、GPSがOFFであることを確認。GPS・初期設定・実SFC・前回作業復元の隣接回帰も成功。
- 再発防止: 方位イベントから `rotationDeg` を直接更新しない。GPS開始処理へ方位追従を結合しない。表示回転で復元スナップショットを作らない。
- 正常基準: `BASE-COMPASS-FOLLOW-20260822`。

## INC-20260822-06 現在地が図面から離れても航空写真が残らない

- 状態: `検証済み`
- 観察: 現在地が図面から500m以上離れていても、現在地周辺の航空写真が表示されないことがあった。
- 根本原因: 現在地用の最新写真を有効にした後、過去年代一覧を確認する別のfetchが失敗すると、表示可能な最新写真まで `aerialPhotoEnabled=false` にしていた。さらに通常ファイル読込み直後で図面座標系が未判定の場合、端末現在地の座標系を図面の座標系と仮定して距離を計算し、別地域でも偶然同じ平面座標値なら近距離と誤判定する経路があった。`fc28eb7` で一度除去した後、`5120e98` の端末既定座標系追加で同じ危険な自動適用が再導入された。GPS座標の微小な揺れを年代検索へ渡し続け、検索開始時に写真候補を空にすることも、現在地写真と別地点写真の点滅原因になった。加えて複数部分図・外れ図形を含むSFCでは、全図形の外接矩形が現在地まで伸びて実距離を過小評価した。現在地座標系への一時切替中も図面保存済みラスターを描き続け、現在地タイルの上へ別地点の画像が非同期に重なる経路があった。
- 修正: `cf87287` で年代確認失敗と最新写真表示を分離。`7e6f76d` で危険な端末共通既定の自動適用を除去した。`bdc4975` で距離範囲を主図面部分へ限定し、距離用メッシュ変換をGPS表示状態から分離した。現在地座標系への一時切替中は図面保存済み航空写真を隠す。`b261d32` では実運用方針を改め、スマホの未設定図面だけ最初の現在地系を図面単位で保存し、以後の移動では上書きしない方式へ変更した。端末共通既定UIは廃止した。
- 検証: `validate-gps-startup-mode.js` でスマホの未設定図面へ現在地の第4系を図面単位で保存すること、端末共通既定UIの不存在、主図面部分と100km離れた別部分図を含む合成データで全体外接矩形の誤距離0mに対して主図面距離99km超となること、GPS一時座標系中の固定メッシュ距離、保存済み航空写真の抑止と復元、現在地最新写真の固定、図面別手動座標系の優先、GPS終了時の状態復元を確認。方位、性能、既定設定、前回作業復元、実SFC読込の隣接回帰も成功。
- 再発防止: 年代スライダー用の通信失敗を最新画像タイルOFFへ連動させない。GPS位置更新から年代検索を再始動しない。全図形の外接矩形を現場範囲と仮定しない。GPS一時座標系で図面座標の保存済み航空写真を描かない。現在地系の自動採用はスマホ・図面未設定・初回GPSの条件に限定し、保存済み図面を移動のたびに上書きしない。
- 正常基準: `BASE-GPS-AERIAL-20260822`。

## INC-20260823-01 ホームで図面枠ではなく内側図形だけが拡大表示される

- 再発防止: ホーム表示と外れ図形除外を同じ目的として扱わない。SXF用紙情報がある場合は図面枠を正本とする。
- 正常基準: `BASE-HOME-SHEET-FIT-20260823`。

## INC-20260822-07 ブラウザを閉じると現場での変更を直接復元できない

- 状態: `検証済み`
- 観察: 自動保存された編集差分は元SFCを開いた後なら復元できるが、iPhoneやAndroidでブラウザを誤って閉じた場合、OneDrive等から元SFCを探し直す必要があった。
- 根本原因: 従来の復元データは元SFCの指紋に紐づく差分だけで、元SFC本体と初回画面から復元を開始する導線を保持していなかった。ブラウザは以前選んだOneDriveのパスを自由に再参照できない。
- 修正: `2f1214d` で元SFCを図面ごとに1回だけIndexedDBの専用ストアへ保存し、初回画面へ「前回の作業を復元」を追加した。編集時は従来どおり差分だけを更新し、大きな写真でlocalStorage保存が失敗してもIndexedDBと復元索引の更新を続ける。
- 検証: `validate-last-work-recovery.js` で、サンプルSFCと手書き・レイヤー色を保存後、localStorageスナップショットを除去してページを再読込し、元ファイル選択なしでIndexedDBから復元した。性能、自動保存、実SFC、GPS、方位の隣接回帰も成功。
- 再発防止: 元SFC全体を編集操作ごとに保存しない。元SFC複製と編集差分を分離する。ブラウザのFile・OneDriveパス・元JPEGを永続参照できると仮定しない。
- 正常基準: `BASE-LAST-WORK-RECOVERY-20260822`。

## INC-20260816-01 DEM1Aがある範囲までDEM5Aへ切り替わる

- 状態: `検証済み`
- 観察: 画面全体のDEM1A取得率を基準に、DEM1Aが存在する場所も含めて全体がDEM5Aへ落ち、等高線が粗く見える経路があった。
- 根本原因: 取得率しきい値による全体fallbackと、Webメルカトルのタイル方向を格子方向へ使う処理。
- 修正: `bb08104` を基準に、DEM1Aの有効値を保持し、欠損点だけDEM5Aで補完。等高線格子を平面座標方向へ合わせる。

- 再発防止:
  - DEM1A取得率だけで画面全体をDEM5Aへ切り替えない。
  - 表示軽量化と標高源の優先順位を別の問題として扱う。
  - 平滑化を精度問題の万能な解決策として追加しない。
- 正常基準: `BASE-TERRAIN-DEM1-20260816`。
