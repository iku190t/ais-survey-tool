# EZ Viewer 外部知能インデックス

このフォルダーは、過去の調査・失敗・修正理由・検証結果・正常コミットを、次回以降のCodexへ引き継ぐための索引です。コードの正本はGitです。この文書群はコードを複製せず、「どの事実を、どの証拠で確認し、どこへ戻せるか」を保存します。

最終確認日: 2026-08-22
確認基準: `main` / `2f1214d`

## 読み分け

|知りたいこと|読む文書|
|---|---|
|現在の構成、公開状態、既知の検証課題|[PROJECT_STATE.md](PROJECT_STATE.md)|
|正常だったコミット、機能別の戻し先|[VERIFIED_BASELINES.md](VERIFIED_BASELINES.md)|
|変更時に守る設計判断、確定仕様|[DECISIONS.md](DECISIONS.md)|
|過去の不具合、原因、再発防止|[INCIDENTS.md](INCIDENTS.md)|
|機能別に実行する検証コマンド|[TEST_MATRIX.md](TEST_MATRIX.md)|
|新しい知見を記録する書式|[ENTRY_TEMPLATE.md](ENTRY_TEMPLATE.md)|

## 状態ラベル

- `観察`: ユーザー報告、画面、ログなどで現象を確認した段階。原因は未確定。
- `再現済み`: 手順またはテストで同じ現象を再現できた段階。
- `検証済み`: 修正後に対象テストまたは実データ確認が成功し、コミットで固定した段階。
- `廃止`: 現在は採用しない仕様、修正、回避策。
- `仮説`: 説明候補。事実として扱わず、検証後に状態を更新する。

## 証拠の優先順位

1. 現行コードと再現テストとコミットが一致している
2. コミット差分と対象テストが一致している
3. 同じ実データまたは操作で複数回確認されている
4. 一度の目視確認またはユーザー報告
5. 会話中の推測

4と5は確定仕様へ昇格させません。仕様書が存在するSXF/SFC処理では、仕様書または正常ファイルとの比較根拠も必要です。

## 更新手順

1. 作業前にGit状態、現在コミット、関連する事故と正常基準を確認する。
2. 観察と仮説を分け、再現手順を作る。
3. 最小範囲を修正し、`TEST_MATRIX.md`の関連テストと実データ確認を行う。
4. 成功した事実だけを該当文書へ追記する。
5. コミットIDと戻し先を記録する。
6. 同じ判断が別件でも確認された場合、確認回数を増やす。2回以上で常設判断への昇格を検討する。

## 記録しないもの

- メールアドレス、住所、認証情報、APIキー、個人名などの個人情報
- 顧客図面、写真、位置座標、現場名などの顧客データ
- 会話全文や未検証の要望一覧
- Gitから復元できるソースコードの丸ごとの複製
